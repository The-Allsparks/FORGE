# HELM

**High-level Execution and Logic Manager**

Progress through vocabulary, static intent trees, validation, observation, and shadow recommendation. Only then — and only with evidence — consider narrowly bounded authority. Preserve Pedro Pathing ownership of chassis movement. Preserve a conventional autonomous fallback.

Authoritative repository: [The-Allsparks/HELM](https://github.com/The-Allsparks/HELM)

## What students learn here

Name the goal, the success condition, the timeout, and the fallback **on paper** before any executor exists. HELM does not make the robot clever. Students do.

## FORGE season use

| Period | Intent | Competition status target |
| ------ | ------ | ------------------------- |
| Preseason | Vocabulary only; HELM has no authority | disabled |
| Kickoff–clinic | Describe or simulate autonomous intent | observe / validate |
| Nov–Dec | Shadow recommendations vs the conventional auto | practice-only shadow |
| Tournament | Frozen off unless a critical demonstrated problem | disabled or frozen-off |

HELM readiness gates were **not met** at audit ([readiness-gates.md](https://github.com/The-Allsparks/HELM/blob/main/docs/readiness-gates.md)). Creating FORGE does not change that.

## Prerequisites

Students can explain the conventional Pedro (or other) autonomous. TRACE should record that auto before any later HELM gate.

## Hardware / simulation

Desktop validation and simulated tree walking only. Physical output is refused in the library.

## Evidence

Written intent tree; `Helm.validate` errors discussed; observe records compared to what the robot actually did.

## Safety

Never directly command motors. Unknown/stale capabilities are unavailable, not "fine." Disable path must not require rewriting Pedro or MIMIC.
